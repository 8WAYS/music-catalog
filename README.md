# Музыкальная картотека

PWA-картотека любимой музыки: владелец ведёт её на телефоне, друзья смотрят по ссылке.
Полная документация — `docs/Музыкальная картотека — документация для разработки.docx`.

## Запуск

```bash
cd app
npm install
npm run dev          # http://localhost:5173
npm test             # модульные и интеграционные тесты (Vitest + fake-indexeddb)
npm run build        # сборка в app/dist
npx playwright install chromium webkit   # один раз
npm run e2e          # e2e-сценарии на мобильных профилях
```

Чтобы открыть dev-сервер с телефона в той же Wi-Fi-сети: `npm run dev -- --host`.
Для проверки PWA и офлайна нужна продакшен-сборка: `npm run build && npm run preview -- --host`.

## Публикация и ссылка для друзей

Клонировать репозиторий и что-то устанавливать нужно только владельцу — чтобы менять код
приложения. Чтобы вести картотеку и смотреть её, репозиторий вообще не нужен: и владелец (со
своего телефона), и друг (по ссылке) просто открывают сайт в браузере.

### Другу — ничего не клонировать, просто ссылка

1. Владелец присылает ссылку вида `https://<логин>.github.io/music-catalog/` (или прямо на
   Витрину/конкретный релиз — ссылки внутри сайта ведут туда же).
2. Друг открывает её в любом браузере — на телефоне или компьютере. GitHub, аккаунт, установка —
   не нужны.
3. Сайт сам определяет, что это чужое устройство (нет сохранённого токена владельца), и открывает
   картотеку в режиме «только просмотр»: смотреть, искать, фильтровать по тегам можно, редактировать
   и закреплять на Витрине — нет.
4. Ссылку можно сохранить на домашний экран телефона (как обычный сайт) — тогда картотека открывается
   иконкой, как отдельное приложение, и работает офлайн с последней загруженной версией.

### Владельцу — первая публикация (один раз)

1. Создать fine-grained token: GitHub → Settings → Developer settings → Fine-grained tokens,
   доступ только к `music-catalog`, Repository permissions → Contents: Read and write, срок 1 год.
2. В приложении: Настройки → Публикация → репозиторий и токен → «Подключить и опубликовать».
   Токен хранится только на этом устройстве, не уходит никуда, кроме самого GitHub.
3. Дальше картотека публикуется сама через 5 секунд после каждого изменения; сайт обновляется
   примерно через минуту (GitHub Actions собирает и выкладывает страницу).
4. Ссылку из шага 2 (`https://<логин>.github.io/music-catalog/`) — отправить друзьям как обычную
   ссылку, в любой мессенджер.
5. Новый телефон владельца: открыть ту же ссылку → Настройки → «Это моя картотека» → ввести токен
   (можно тот же, что и раньше, если не истёк).

### Другу — если хочет не смотреть, а завести свою картотеку

Это тот же код в отдельном репозитории — устанавливать ничего на компьютер не нужно, всё делается
в браузере через GitHub. Копия полностью независима: свои данные, свой репозиторий, свой токен, с
оригиналом никак не связана.

1. Открыть репозиторий проекта на GitHub → кнопка **Fork** → форкнуть на свой аккаунт.
2. В своём форке: **Settings → Pages → Build and deployment → Source** → выбрать **GitHub Actions**
   (по умолчанию выключено — разовая настройка).
3. Вкладка **Actions** → workflow **Deploy to GitHub Pages** → **Run workflow** — запустить вручную
   один раз (без этого сайт не соберётся, пока не будет своего коммита).
4. Через минуту сайт готов на `https://<его-логин>.github.io/music-catalog/` — картотека пустая.
5. Дальше — как в разделе «Владельцу» выше: создать свой fine-grained token и подключить публикацию
   в Настройках приложения.

Страница проверки внешних сервисов (этап 0): `https://<логин>.github.io/music-catalog/probe.html`.

Свой домен: файл `CNAME` в корне репозитория с именем домена — deploy.yml скопирует его на сайт.

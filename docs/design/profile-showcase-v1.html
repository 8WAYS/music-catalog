Топ — обычный плейлист с датой в названии, тот же механизм полки

Аура — из цветов закреплённых обложек, как на карточке релиза. Полки — горизонтальный скролл со snap, не грид: подборка короткая нарочно, никакой пагинации.

Как закрепляют

Владелец, не отдельный редактор

Ничего нового не вводим для этого — используем то, что уже есть в интерфейсе:

  • Долгое нажатие на обложку или артиста в обычной картотеке — «Закрепить на витрине» (то же самое действие уже в списке «известные мелочи» этапа 7 для другого — можно сделать оба сразу).
  • На самой витрине — перетаскивание внутри полки, чтобы менять порядок.
  • «Топ месяца» — заводится как обычный плейлист с названием вроде «Сентябрь 2026»; отдельного интерфейса не нужно, если плейлисты уже проектируются.

Модель данных

Что понадобится добавить

  • Избранный релиз — сейчас звёздочка есть только у отдельного трека (Track.favorite), у альбома целиком — нет. Добавить Release.pinned?: boolean (или сразу pinnedOrder?: number, чтобы порядок на полке был не «как в базе», а ручной).
  • Избранные артисты — в модели нет отдельной сущности «артист» (только строка Release.artist). Нужен минимальный новый список в meta или отдельная коллекция: имя + id представительного релиза (для обложки/цвета аватара).
  • Плейлист / топ — новая сущность: имя, упорядоченный список id релизов. Топ месяца — такой же плейлист, просто с датой в названии; отдельная модель не нужна.
  • Ничего из этого не требует FORMAT_VERSION++ — только новые опциональные поля и коллекции, старые данные валидны как есть (как было с обложками из iTunes/Spotify).

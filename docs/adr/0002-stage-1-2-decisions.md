# ADR 0002. Решения этапов 1–2

Статус: принято · 2026-09-25

1. **Формат обложки.** Safari (iOS), насколько известно, не кодирует WebP из canvas — `toBlob("image/webp")` отдаёт PNG (подтвердить на этапе 0, строка «Canvas → WebP» в probe.html).
   Приложение пробует WebP, иначе сохраняет JPEG; имя файла отражает формат — `covers/<id>.webp` или `covers/<id>.jpg`.
   Размер ≤ 100 КБ достигается понижением качества.
2. **Определение режима до этапа 5.** Владелец — если на устройстве есть токен **или локальные данные**;
   иначе, если опубликован `data/catalog.json`, — зритель; иначе — новая пустая картотека владельца.
   Так можно вести картотеку до настройки публикации, а друзья с пустым браузером видят опубликованную версию.
3. **Шрифты** — Unbounded + Onest из npm-пакетов @fontsource-variable. Service worker заранее кэширует только
   латиницу и кириллицу, остальные подмножества грузятся по unicode-range.
4. **Треклист вставкой.** В поле трека можно вставить список целиком — нумерация («1.», «01 -», «A1») и длительность
   («3:45») распознаются. Нумерация через пробел («1 Song») убирается, только если все строки пронумерованы подряд,
   чтобы не портить названия вроде «7 Rings».
5. **Уникальность тегов** без учёта регистра обеспечивает Repository: повторное создание возвращает существующий тег.
6. **Цвет из обложки** считается при выборе картинки (медианное сечение 64×64), сохраняется в `coverColors`.
   Проверка контраста покрыта тестами (accent ≥ 3:1, text ≥ 4.5:1 к bg).
7. **Экран поиска MusicBrainz** (#/add) пока ведёт в ручной редактор — этап 4.

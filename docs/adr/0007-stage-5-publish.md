# ADR 0007. Решения этапа 5 (публикация и режим зрителя)

Статус: принято · 2026-09-25 · уточняет ADR 0002, п. 2

1. **Режим** (`src/data/mode.ts`). Владелец — устройство с токеном GitHub. Без токена: картотека опубликована —
   зритель; не опубликована — своя локальная картотека (как до настройки публикации); сайт не ответил за 6 с —
   владелец, если есть свои данные, иначе зритель с сохранённой копией. Раньше владельцем делали и локальные
   данные — тогда друг, заглянувший до публикации, так и не увидел бы картотеку владельца. Свои данные у него
   сохраняются: в настройках «Открыть свою картотеку» (флаг `preferLocal` в localStorage) и обратно.
2. **Новое устройство владельца** — «Это моя картотека» у зрителя: токен → проверка → если своих данных нет,
   загрузка опубликованной версии (`importPublished`); если есть — после перезапуска публикация покажет конфликт.
   После смены режима приложение перезапускается на главной.
3. **Публикация — один коммит Git Data API**: дерево на базе текущего, `catalog.json` текстом прямо в дереве,
   обложки blob'ами. Загружаются только новые и изменённые обложки — сравниваем git-хэш локального файла
   (sha1 от `blob <размер>\0` + байты) с деревом `data/`; обложки удалённых релизов убираются (`sha: null`).
4. **Конфликт — по `catalog.json`, а не по голове ветки.** Коммиты кода двигают `main`, но конфликтом не являются.
   Храним git-хэш опубликованного нами `catalog.json` (`meta.catalogSha`); на сайте другой — картотеку меняли
   в другом месте, пользователь выбирает «Взять с сайта» или «Оставить мою». Ветку сдвинули между чтением
   и записью (422 на PATCH) — перечитываем и повторяем один раз.
5. **Автопубликация** через 5 с после последнего изменения; «грязно» снимается, только если ревизия не выросла
   за время публикации. Очередь при офлайне — это флаг `dirty`: публикуем при событии `online`, при возврате
   в приложение (`visibilitychange`) и при запуске. Сбои GitHub и таймауты — повтор через минуту; неверный токен
   и нет прав — ждём исправления в настройках. Хранилище `queue` из раздела 4.6 не понадобилось.
6. **Проверка доступа** — чтение ветки и пробная запись blob без коммита: права fine-grained токена из
   `GET /repos` не видны, а blob без коммита ни на что не влияет.
7. **Зритель** — `catalog.json?v=<время>` в обход кэша CDN, таймаут 10 с, один повтор, затем копия из
   Cache Storage с пометкой «сайт не ответил, показана сохранённая версия». Обложки кэширует service worker
   (CacheFirst: в адресе версия `?v=updatedAt`).
8. **Тесты**: Git Data API в памяти (`tests/fakeGithub.ts`) с настоящими git-хэшами — общий для unit и e2e.
   В e2e service worker отключён: запросы через него не видит `page.route`. Тестовые данные в e2e — с UUID,
   иначе валидация не даёт сохранить правку.

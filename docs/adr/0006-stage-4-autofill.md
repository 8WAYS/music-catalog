# ADR 0006. Решения этапа 4 (автозаполнение из iTunes)

Статус: принято · 2026-09-25 · дополняет ADR 0004

1. **Поток.** «+» и «Добавить альбом» ведут на поиск `#/add`; «Заполнить вручную» всегда внизу и переносит
   набранные название и исполнителя в редактор. Выбор результата грузит треклист и обложку параллельно
   и открывает редактор `#/new` с заполненными полями — сохраняет пользователь сам.
2. **Передача в редактор** — одноразовый черновик `setEditorSeed` / `takeEditorSeed` (`src/store/app.ts`):
   поля релиза и уже сжатая обложка. Редактор с черновиком считается изменённым — уход спросит подтверждение.
3. **Частичный успех лучше отказа.** Не загрузился треклист или обложка — редактор всё равно открывается,
   тост подсказывает, что добавить руками.
4. **Поиск по кнопке**, без поиска на каждую букву: лимит iTunes ~20 запросов в минуту. Результаты и поля живут
   в модуле экрана — «Назад» из редактора возвращает к ним; после сохранения нового релиза поиск очищается.
5. **Версии одного альбома схлопываются** по названию, исполнителю, году и числу треков (clean/explicit),
   делюкс с другим числом треков остаётся отдельной строкой.
6. **Ошибки — текстом для человека** (`LookupError`): нет связи, таймаут 10 с (в Safari это `AbortError`),
   лимит (iTunes отвечает 403), сбой сервера.
7. **Формат 2** (`FORMAT_VERSION` 2): `mbid` → `itunesId` (collectionId). Миграция 1 → 2 убирает `mbid`.
8. **Обложки в IndexedDB — байты и тип (`{ type, data: ArrayBuffer }`), а не Blob.** WebKit в приватном режиме
   (и в Playwright) не кладёт Blob в IndexedDB: «Error preparing Blob/File data to be stored in object store».
   Старые записи-Blob читаются как есть, версия схемы IndexedDB не меняется.
9. **e2e не ходят в iTunes**: ответы подменяются через `page.route` — тесты не зависят от сети и лимитов.
   Живой поиск проверен вручную.

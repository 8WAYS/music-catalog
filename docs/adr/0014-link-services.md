# ADR 0014. Ссылки «Слушать»: фильтр площадок в настройках, поиск на других площадках

Статус: принято · 2026-09-30

## Контекст

Запрос: (1) в настройках скрывать площадки, которыми человек не пользуется (например, оставить
только Spotify), чтобы на карточке релиза не мозолили глаза чужие ссылки; (2) по уже известным
данным о релизе (название, артист) находить и добавлять ссылку на другую площадку одной кнопкой,
не вбивая вручную.

По второй части проверили вживую: бесплатного API кросс-платформенного сопоставления треков, который
знал бы про Яндекс.Музыку и VK Музыку, не существует. song.link/Odesli — единственный сколько-нибудь
известный сервис такого рода — публично недоступен с июля 2026 (прямой запрос вернул `401
PUBLIC_API_ACCESS_DEPRECATED`), а их преемник SongPort вообще не знает ни про Яндекс.Музыку, ни про
VK Музыку (покрывает только Spotify/Apple Music/YouTube Music/Tidal/SoundCloud). Официального
бесплатного поиска у Яндекс.Музыки и VK Музыки для сторонних приложений тоже нет. Фиксируем это
здесь, чтобы через полгода кто-то не переоткрывал тот же вопрос заново.

## Решение

### 1. Фильтр отображаемых площадок — личная настройка устройства

`hiddenLinkServices` (`src/store/app.ts`) — сигнал со списком скрытых `LinkService`, по тому же
`readPref`-паттерну, что `theme`/`reduceMotion` (localStorage, try/catch). Это НЕ часть
`catalog.json` — у владельца и у зрителя разные привычки слушать музыку, поэтому настройка не
синхронизируется и доступна в разделе «Оформление» и владельцу, и зрителю без `owner &&`-обёртки (в
отличие от большинства настроек `Settings.tsx`, которые видит только владелец). Применяется в
`Release.tsx` — ссылки фильтруются до рендера и до проверки, есть ли что показывать вообще (весь
блок пропадает, если скрыты все площадки).

### 2. Поиск ссылок — асимметрично по сервисам

Из-за отсутствия открытого API для Яндекс/VK (см. «Контекст») кнопки в `LinksEditor.tsx` не
одинаковые:
- **Spotify** — точный автопоиск через уже существующий поиск по Spotify Web API
  (`services/spotify.ts`, ADR 0010) по названию и артисту релиза. Если релиз изначально добавлен
  через Spotify-поиск, у него уже есть `spotifyId` — тогда ссылка строится напрямую
  (`spotifyAlbumUrl(id)`), без похода в сеть.
- **Яндекс/VK** — кнопка просто открывает страницу поиска на их сайте с подставленным «артист
  название» (`yandexSearchUrl`/`vkSearchUrl`, `services/links.ts`). Это ручное конструирование URL,
  не официальный API — помечено комментарием в коде, что может сломаться при смене вёрстки/маршрутов
  сайта. Ссылку из результатов поиска пользователь копирует и добавляет сам через уже существующее
  поле ручного ввода — автоматически в `Link[]` ничего не пишется.

Кнопка сервиса не показывается, если ссылка этого сервиса уже добавлена (нет смысла искать снова), а
кнопка Spotify — если Spotify не подключён и `spotifyId` нет (нерабочая кнопка не показывается вовсе,
не показывает ошибку по клику).

Ни `Release`, ни `Link`, ни `FORMAT_VERSION` не меняются — обе фичи работают поверх уже существующей
модели (`Link { service, url }`), автопоиск лишь предлагает `url`, ничем не отличаясь от вбитого
вручную.

## Изменённые файлы

`src/store/app.ts` (сигнал+сеттер), `src/services/links.ts` (URL-хелперы), `src/screens/Settings.tsx`
(чекбоксы площадок), `src/screens/Release.tsx` (фильтрация при рендере), `src/components/
LinksEditor.tsx` (кнопки поиска), `src/screens/Editor.tsx` (проброс `title`/`artist`/`spotifyId`).

## Проверка

`tests/unit/app.test.ts` — `setLinkServiceHidden` (включение/выключение, персистентность, устойчивость
к битому JSON). `tests/unit/links.test.ts` — корректный `encodeURIComponent` в URL-хелперах.
`tests/e2e/link-filter.spec.ts` — скрытая площадка не отображается на карточке, скрыть все — блок не
рендерится, настройка переживает перезагрузку. `tests/e2e/spotify-add.spec.ts` (новые кейсы,
переиспользуют существующие `mockSpotify`/`seedSpotifyConnected`) — автопоиск без `spotifyId` бьёт в
мокнутый `/search` и добавляет ссылку; с `spotifyId` — строит ссылку без сетевого запроса; кнопка не
видна без подключения и без `spotifyId`; кнопки Яндекс/VK формируют правильный URL и ничего не
добавляют сами; кнопка сервиса пропадает, когда ссылка уже есть.
